# MP4Box.js engine

> Scope: This page owns the MP4Box.js [adapter](../glossary.md)'s [ISO BMFF](../glossary.md) probe, demux, remux, and mux behavior; generic runner, [oracle](../glossary.md), and [scenario](../glossary.md)-family policy remain with their subsystem and feature pages.
> Phase-2 owner: p2_engine_mp4box.

## Purpose

The MP4Box.js [engine](../glossary.md) measures what a browser-side, pure-JavaScript ISO Base Media File Format ([ISO BMFF](../glossary.md)) parser and writer can do without decoding or encoding media. Readers use this page to decide which results demonstrate box/sample-table handling, which results only demonstrate representation agreement with a [golden](../glossary.md), and which combinations are outside the adapter's real support boundary.

The page is also the hand-off specification for later cleanup of this adapter: capability honesty, sample-entry preservation, presentation-timeline fidelity, completion/error handling, and bounded resource use must be fixed here without attributing decoder behavior to MP4Box.js.

### Whole-file parsing and normalized probe metadata

Probe, demux, remux, and mux preparation begin by materializing `MediaInput.arrayBuffer()`. `parseToInfo()` creates an ISOFile, installs `onReady` and `onError`, appends one `MP4BoxBuffer` at offset zero, calls `flush()`, and rejects when neither callback resolves the file. `keepMdatData` is false for probe and true for sample extraction/remux. [src/engines/mp4box/adapter.ts:702-745](../../src/engines/mp4box/adapter.ts#L702-L745) [src/engines/mp4box/adapter.ts:748-768](../../src/engines/mp4box/adapter.ts#L748-L768) [src/engines/mp4box/adapter.ts:806-814](../../src/engines/mp4box/adapter.ts#L806-L814) [src/engines/mp4box/adapter.ts:905-920](../../src/engines/mp4box/adapter.ts#L905-L920)

That `createFile(true)` distinction is required by the installed API: GPAC documents that media data is discarded by default from 1.0 onward and must be retained for rewriting or sample access. The adapter applies that rule to demux, mux preparation, and remux, while probe takes the lower-retention path. [GPAC's TypeScript/`mdat` migration note](https://gpac.io/2025/06/19/announcing-mp4box-js-1-0-0-with-typescript-support/) explains the upstream contract. [src/engines/mp4box/adapter.ts:712-718](../../src/engines/mp4box/adapter.ts#L712-L718) [src/engines/mp4box/adapter.ts:749-755](../../src/engines/mp4box/adapter.ts#L749-L755) [src/engines/mp4box/adapter.ts:813-814](../../src/engines/mp4box/adapter.ts#L813-L814) [src/engines/mp4box/adapter.ts:919-920](../../src/engines/mp4box/adapter.ts#L919-L920)

Probe normalization maps handler kinds to `video`, `audio`, `subtitle`, or `other`. Codec strings canonicalize AVC sample entries to `h264`, HEVC entries to `hevc`, VPx/AV1 entries to their canonical names, and `mp4a`/AAC, Opus, MP3, and FLAC forms to the suite tokens; an unknown token is retained lowercased. For CENC-style protected entries, the adapter walks `stsd` → encrypted sample entry → `sinf` → `frma` and canonicalizes the original format when that box tree is available; failure falls back to the wrapper codec rather than aborting probe. ### Demux and packet observation

Demux configures extraction for every track with batches of up to 100,000 samples, starts and flushes synchronously, copies scalar observations, releases MP4Box.js sample memory through the last emitted sample number, and stops. It converts `cts`, `dts`, and duration units using each sample's [timebase](../glossary.md), maps `is_sync` to `keyframe`, and sorts the global result by DTS then track index. [src/engines/mp4box/adapter.ts:758-803](../../src/engines/mp4box/adapter.ts#L758-L803)

`PacketInfo.trackIndex` is deliberately the index of the corresponding normalized track: an MP4 track id is mapped to its position in `info.tracks` before samples are emitted. `size` is MP4Box.js's encoded sample size, and no sample payload or codec configuration is returned by the normalized `DemuxResult`. [src/engines/mp4box/adapter.ts:770-786](../../src/engines/mp4box/adapter.ts#L770-L786) [src/core/engine.ts:63-74](../../src/core/engine.ts#L63-L74)

For scenarios using [golden packets](../glossary.md), the current [oracle](../glossary.md) groups both tables by numeric track index, sorts each track by DTS/PTS, requires equal packet count and track-index layout, requires byte-exact size and keyframe flags, and tolerates timestamps only after removing a constant per-track origin offset. [src/core/oracles.ts:835-926](../../src/core/oracles.ts#L835-L926) `golden-packets` emits only a boolean `pass`; any non-gap mismatch becomes cell [FAIL](../glossary.md), because neither `OracleOutcome` nor `ResultStatus` contains [DIFF](../glossary.md). [src/core/oracles.ts:972-984](../../src/core/oracles.ts#L972-L984) [src/core/scenario.ts:208-222](../../src/core/scenario.ts#L208-L222) [src/core/runner.ts:1411-1447](../../src/core/runner.ts#L1411-L1447)

### MP4Box-prepared mux path

`prepareMuxTracks()` parses every input with media retention, extracts and copies all non-empty video/audio samples, releases MP4Box.js's copies after each callback, and ignores subtitle/other tracks. It keeps native `cts`, `dts`, duration ticks and a copied payload for each chunk. [src/engines/mp4box/adapter.ts:806-848](../../src/engines/mp4box/adapter.ts#L806-L848)

Each prepared track carries a source sample-entry type and every child description box except `sinf`. A protected sample entry is rejected because the adapter does not decrypt it. The code chooses one sample entry for a track and does not preserve a per-sample description index. [src/engines/mp4box/adapter.ts:246-255](../../src/engines/mp4box/adapter.ts#L246-L255) [src/engines/mp4box/adapter.ts:498-522](../../src/engines/mp4box/adapter.ts#L498-L522) [src/engines/mp4box/adapter.ts:850-895](../../src/engines/mp4box/adapter.ts#L850-L895)

Explicit selectors such as `video:0@0` and `audio:0@1` are honored. Without selectors, a single input keeps all audio/video candidates; multiple inputs select all video from input zero plus all audio from later inputs, with an audio-only fallback when input zero has no video. [src/engines/mp4box/adapter.ts:549-585](../../src/engines/mp4box/adapter.ts#L549-L585)

Before mux, each prepared track is independently rebased so its minimum PTS/DTS becomes zero, both in microseconds and native ticks. This preserves intra-track deltas but removes original per-track origins and therefore can remove relative track offsets. [src/engines/mp4box/adapter.ts:525-547](../../src/engines/mp4box/adapter.ts#L525-L547) [src/engines/mp4box/adapter.ts:867-880](../../src/engines/mp4box/adapter.ts#L867-L880)

`mux()` accepts only `container: "mp4"`, at least one non-empty audio/video track, and tracks bearing the adapter's private MP4Box provenance. It initializes brands `isom`, `iso6`, and `mp41`, authors one sample entry per track with copied description boxes, preserves native timing when present, rejects negative composition offsets, calls `addSample`, then serializes `getBuffer()`. Apart from `container`, output-shape options such as `fragmented`, `fastStart`, `target`, and `writeChunkBytes` are ignored. [src/engines/mp4box/adapter.ts:971-1046](../../src/engines/mp4box/adapter.ts#L971-L1046)

### Fragmenting remux path

`remux()` is not a general container copier. It accepts only an MP4 target, retains `mdat`, requires at least one track, configures every track for 1,000-sample RAP-aligned segments, obtains one combined initialization segment, collects every `onSegment` buffer, and concatenates the initialization segment and media segments into one `video/mp4` result. [src/engines/mp4box/adapter.ts:905-943](../../src/engines/mp4box/adapter.ts#L905-L943) This follows MP4Box.js's documented [segmentation API](https://github.com/gpac/mp4box.js/blob/v2.3.0/README.md#segmentation), but it buffers all fragments and performs a final copy rather than exposing progressive writes. [src/engines/mp4box/adapter.ts:475-486](../../src/engines/mp4box/adapter.ts#L475-L486) [src/engines/mp4box/adapter.ts:924-943](../../src/engines/mp4box/adapter.ts#L924-L943)

The method does not inspect the scenario's other shape options, does not prove that any media segment arrived, and does not validate the produced fragment graph before returning. A second-remux feature is intentionally undeclared because the adapter records that re-fragmenting its own output failed during prior implementation work. [src/engines/mp4box/adapter.ts:672-677](../../src/engines/mp4box/adapter.ts#L672-L677) [src/engines/mp4box/adapter.ts:913-943](../../src/engines/mp4box/adapter.ts#L913-L943)

## Target design and known gaps

### Target design

1. **Negotiate concrete tuples, then use runtime NA precisely.** Define support by operation × input container × track/sample-entry set × output container × output mode. Until the shared capability model can encode that tuple, validate it inside the adapter before doing work and throw NotApplicableError for an ordinary unsupported combination so the runner records NA_ENGINE. A malformed file after a supported tuple is selected must remain FAIL/ERROR, not be disguised as NA. MP4Box.js exposes distinct information, extraction, segmentation, and sample-writing surfaces in its [versioned API documentation](https://github.com/gpac/mp4box.js/blob/v2.3.0/README.md#api); those distinct surfaces are the natural operation boundaries.

   Acceptance: `fragmented` is scoped to remux unless mux genuinely authors fragments; mux `fastStart`, streaming-target, unsupported sample-entry, multi-description, and negative-composition tuples either produce the requested shape or return NA_ENGINE before an oracle sees bytes. Non-MP4 remux and track sets that cannot be segmented use NotApplicableError. The hand-maintained disabled-cell list does not grow for ordinary MP4Box.js applicability decisions.

2. **Make advertised features observable.** `webcodecs:demux-feed` must be removed until `DemuxResult` exposes access-unit payloads plus codec description, or the result contract must be extended and the adapter must populate them. For AVC, a present decoder `description` is an `AVCDecoderConfigurationRecord` and chunks use the length-prefixed AVC form; without it chunks are [Annex B](../glossary.md), according to the [W3C AVC registration](https://www.w3.org/TR/webcodecs-avc-codec-registration/#videodecoderconfig-description). HEVC has the analogous `HEVCDecoderConfigurationRecord`/canonical-versus-Annex B distinction in the [W3C HEVC registration](https://www.w3.org/TR/webcodecs-hevc-codec-registration/#videodecoderconfig-description). A capability is accepted only when a scenario consumes and validates that observable output.

3. **Preserve format configuration and presentation semantics.** Keep the active sample-description index per sample, preserve required `avcC`, `hvcC`, `vpcC`, `av1C`, `esds`, and related boxes, and reject rather than silently flatten tracks that change sample entry. The MP4 Registration Authority identifies these boxes as codec configuration inside `stsd` sample entries on its [sample-entry box registry](https://mp4ra.org/registered-types/sample-entry-boxes), while [ISO/IEC 14496-15:2024](https://www.iso.org/standard/89118.html) defines AVC/HEVC NAL-unit carriage in ISO BMFF.

   Preserve a common movie presentation timeline: retain or reconstruct edit-list offsets, media start, composition offsets, and inter-track A/V offsets instead of independently zeroing every track. The W3C [ISO BMFF byte-stream format](https://www.w3.org/TR/mse-byte-stream-format-isobmff/#initialization-segments) requires support for a single rate-one edit mapping media composition time to movie presentation time. Acceptance fixtures cover positive empty edits, media-time trims, B-frame composition offsets, AAC [priming](../glossary.md), distinct track timebases, and A/V tracks with different origins; probe/remux/mux remain semantically aligned after re-import.

4. **Normalize metadata semantically, without hiding the encoded view.** Keep the adapter's codec canonicalization and protected-entry unwrap, but parse the complete AAC `AudioSpecificConfig` or expose both coded-core and presentation values. The [WebCodecs](../glossary.md) [AAC registration](https://www.w3.org/TR/webcodecs-aac-codec-registration/#fully-qualified-codec-strings) distinguishes AAC-LC, HE-AAC v1, and HE-AAC v2 and treats `AudioSpecificConfig` as authoritative decoder description. ETSI's [HE-AAC v2 decoder model](https://www.etsi.org/deliver/etsi_TS/102000_102099/102005/01.02.01_60/ts_102005v010201p.pdf) shows SBR output at twice the AAC-core rate and [Parametric Stereo](../glossary.md) reconstruction from a mono core to stereo.

   The owning [oracle-system page](../subsystems/oracle-system.md) must compare [golden metadata](../glossary.md) by semantic track type rather than numeric index; canonicalize `avc1`/`avc3` to H.264, `hev1`/`hvc1` to HEVC, `V_MPEG4/ISO/AVC` to H.264, and `mp4a` to AAC; accept documented [HE-AAC/SBR](../glossary.md) base-versus-2× rate and Parametric Stereo 1-versus-2-channel views; band VFR/[NTSC rate](../glossary.md) fps; and widen duration for edit-list, priming, and timebase effects. Adapter diagnostics should retain the raw sample-entry/codec token and timing basis so a semantic PASS remains auditable.

5. **Separate packet semantics from representation diagnostics.** Replace the binary oracle result with [PASS](../glossary.md) / [DIFF](../glossary.md) / [FAIL](../glossary.md). A legal conversion between ISO BMFF length-prefixed AVC/HEVC and Annex B, movement of SPS/PPS/VPS between a configuration record and samples, or legal regrouping of NAL units/access units must be DIFF when decoded content, timing, track attribution, and random-access semantics are preserved. The [AVC registration](https://www.w3.org/TR/webcodecs-avc-codec-registration/#encodedvideochunk-data) and [HEVC registration](https://www.w3.org/TR/webcodecs-hevc-codec-registration/#encodedvideochunk-data) explicitly distinguish canonical length-prefixed and Annex B forms; the [MSE ISO BMFF format](https://www.w3.org/TR/mse-byte-stream-format-isobmff/#initialization-segments) permits codec configuration out of band and recommends support for codecs carrying it in band.

   Acceptance: `golden-packets` keeps exact packet size/keyframe/grouping as representation diagnostics, not universal validity conditions. It fails true sample loss/duplication, timing-order corruption, wrong track attribution, undecodable output, or broken random access; it returns DIFF for a valid representation-only mismatch against the ffmpeg-baked golden. Tests pair `avc1`/`avc3`, `hvc1`/`hev1`, [AVCC](../glossary.md)/Annex B, inline/out-of-band parameter sets, and different legal NAL grouping.

6. **Prove fragment and writer completion.** Fragmented output must contain a valid initialization segment and at least one complete media segment for non-empty media. For MSE-style ISO BMFF, the initialization segment is `ftyp` + `moov` with `mvex`, while a media segment is optional `styp` + `moof` + one or more `mdat`; referenced samples must be present and each `traf` needs `tfdt`, as specified by the [W3C ISO BMFF byte-stream format](https://www.w3.org/TR/mse-byte-stream-format-isobmff/#media-segments). Honor the requested output mode or return NA_ENGINE; do not return a plausible MIME type for init-only or incomplete bytes.

7. **Bound memory and make cleanup/cancellation deterministic.** Feed MP4Box.js progressively or by ranges where the input contract permits, release samples immediately after the last consumer, and stream fragments to an observable sink rather than retaining and concatenating them. Keep operation errors active through extraction/segmentation completion; call `stop()` and release state from `finally`; make abort stop parser work before resolving. MP4Box.js officially documents progressive `appendBuffer`, `stop`, `flush`, and `releaseUsedSamples` in its [2.3.0 API](https://github.com/gpac/mp4box.js/blob/v2.3.0/README.md#api).

   Acceptance: truncated `moov`, truncated `mdat`, incomplete `moof`/`mdat`, callback errors after `onReady`, an init-only fragmented file, and a zero-sample media track never silently succeed. A long-file test records bounded peak memory, an abort test terminates promptly, and every failure path proves `stop()`/release cleanup without changing the primary verdict.

### Known gaps

1. **Capability and output-mode leakage.** **Current:** the flat `fragmented` feature is declared once, remux always fragments, and mux ignores `fragmented` and all other output-shape options after the runner has admitted the cell. Non-MP4 and no-track remux paths both throw generic errors even though only the former is an ordinary unsupported combination. [src/engines/mp4box/adapter.ts:630-680](../../src/engines/mp4box/adapter.ts#L630-L680) [src/engines/mp4box/adapter.ts:913-943](../../src/engines/mp4box/adapter.ts#L913-L943) [src/engines/mp4box/adapter.ts:971-1046](../../src/engines/mp4box/adapter.ts#L971-L1046) **Consequence:** a combinatorially unsupported cell can leak past preflight and become FAIL/ERROR, while a progressive-output scenario can receive fragmented bytes without an output-shape oracle. **Target:** scope capabilities by tuple and use NotApplicableError for runtime inability; keep malformed or trackless applicable inputs in the failure path; only declare a shape that the operation actually authors, consistent with MP4Box.js's separate [segmentation API](https://github.com/gpac/mp4box.js/blob/v2.3.0/README.md#segmentation). **Verification:** exercise every remux/mux × progressive/fragmented/fast-start/stream combination and require requested bytes or NA_ENGINE, never accidental FAIL/ERROR; separately require a genuinely trackless MP4 to fail as invalid input.

2. **Representation-biased packet verdict.** **Current:** the shared comparator requires exact packet count, track-index multiset, size, and keyframe flags, then the boolean result collapses every real mismatch to FAIL. [src/core/oracles.ts:835-926](../../src/core/oracles.ts#L835-L926) [src/core/oracles.ts:972-984](../../src/core/oracles.ts#L972-L984) [src/core/scenario.ts:213-222](../../src/core/scenario.ts#L213-L222) **Consequence:** valid Annex B versus length-prefixed AVC/HEVC, inline parameter sets, or legal NAL/sample grouping can be reported as wrong merely because they differ from the ffmpeg-baked representation. **Target:** classify semantic preservation as PASS, legal [representation difference](../glossary.md) as DIFF, and actual corruption/loss as FAIL, using the distinctions in the [AVC](https://www.w3.org/TR/webcodecs-avc-codec-registration/) and [HEVC](https://www.w3.org/TR/webcodecs-hevc-codec-registration/) registrations. **Verification:** decode-equivalent framing/configuration variants return DIFF; a removed access unit, broken timestamp order, or unusable random-access point returns FAIL.

3. **Presentation timeline is flattened.** **Current:** mux preparation independently subtracts each track's minimum timestamp, and the writer authors durations from the rebased sample endpoints without copying an edit list. [src/engines/mp4box/adapter.ts:525-547](../../src/engines/mp4box/adapter.ts#L525-L547) [src/engines/mp4box/adapter.ts:867-895](../../src/engines/mp4box/adapter.ts#L867-L895) [src/engines/mp4box/adapter.ts:991-1021](../../src/engines/mp4box/adapter.ts#L991-L1021) **Consequence:** valid A/V lead/lag, edit-list offsets, negative composition relationships, and priming presentation can change even when intra-track deltas remain intact. **Target:** preserve the movie presentation mapping described by the [ISO BMFF edit-list requirement](https://www.w3.org/TR/mse-byte-stream-format-isobmff/#initialization-segments), or return NA_ENGINE for a timeline the writer cannot represent. **Verification:** probe and timestamp-aware decode comparisons agree before/after mux for offset, edit-list, B-frame, and primed-AAC fixtures.

4. **AAC and average-fps metadata expose only one view.** **Current:** AAC parsing reads the first two `AudioSpecificConfig` bytes into one sample-rate/channel pair, and video fps is `sample count / duration`. [src/engines/mp4box/adapter.ts:309-405](../../src/engines/mp4box/adapter.ts#L309-L405) [src/engines/mp4box/adapter.ts:421-458](../../src/engines/mp4box/adapter.ts#L421-L458) **Consequence:** explicit or implicit HE-AAC/SBR and Parametric Stereo can expose a core rather than reconstructed view, while VFR or rational NTSC cadence can differ from a golden nominal value. **Target:** parse/label coded and presentation views and let semantic metadata comparison accept the documented HE-AAC equivalences and fps bands; AAC identities and configuration authority are defined by the [AAC registration](https://www.w3.org/TR/webcodecs-aac-codec-registration/), with the 2×/mono-to-stereo behavior shown in [ETSI TS 102 005](https://www.etsi.org/deliver/etsi_TS/102000_102099/102005/01.02.01_60/ts_102005v010201p.pdf). **Verification:** HE-AAC v1/v2 and VFR/30000÷1001 fixtures avoid false FAIL while still detecting a truly wrong output rate, channel layout, or cadence.

5. **Completion and cleanup are inferred.** **Current:** `onReady` permanently suppresses later `onError`; extraction/segmentation use start/flush/stop without `finally`; remux accepts zero media callbacks and buffers/copies all segments. [src/engines/mp4box/adapter.ts:717-745](../../src/engines/mp4box/adapter.ts#L717-L745) [src/engines/mp4box/adapter.ts:776-803](../../src/engines/mp4box/adapter.ts#L776-L803) [src/engines/mp4box/adapter.ts:924-943](../../src/engines/mp4box/adapter.ts#L924-L943) **Consequence:** late parse failures can be hidden, error cleanup is nondeterministic, init-only output can escape, and peak memory grows with input/output size. **Target:** retain error observation through completion, validate sample/segment totals and the normative fragment structure, and use MP4Box.js's documented [progressive/release controls](https://github.com/gpac/mp4box.js/blob/v2.3.0/README.md#extraction) for bounded, cancellable operation. **Verification:** corruption, zero-sample, large-file, and abort tests assert verdict, output completeness, callback completion, cleanup, and memory ceiling.

6. **`webcodecs:demux-feed` is not an observable contract.** **Current:** the feature is declared, but normalized demux returns metadata plus scalar packet observations only; no chunk payload or decoder configuration can reach a WebCodecs decoder. [src/engines/mp4box/adapter.ts:658-680](../../src/engines/mp4box/adapter.ts#L658-L680) [src/core/engine.ts:63-74](../../src/core/engine.ts#L63-L74) **Consequence:** the token can suggest an integration that no scenario can verify. **Target:** remove it or add access-unit bytes and the codec-specific description required by the [WebCodecs AVC](https://www.w3.org/TR/webcodecs-avc-codec-registration/#videodecoderconfig-description) and [HEVC](https://www.w3.org/TR/webcodecs-hevc-codec-registration/#videodecoderconfig-description) registrations. **Verification:** a feature-gated scenario configures a neutral browser decoder from the returned description and decodes the returned chunks, including both out-of-band and in-band parameter-set fixtures.
