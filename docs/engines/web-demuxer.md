# web-demuxer engine

> Scope: This page owns the web-demuxer 4.0.0 adapter, its pinned JavaScript/WASM boundary, its adapter-local progressive ISO BMFF sample-table path, and its probe, demux, WebCodecs decode, and seek behavior. Shared runner, oracle, fixture, and feature-family policy is described here only where it determines this engine's result.
> Phase-2 owner: p2_engine_web_demuxer.

## Purpose

The web-demuxer [engine](../glossary.md) measures a browser integration in which an FFmpeg-derived WebAssembly parser runs in the package's bundled worker and hands metadata, packets, decoder configuration, and encoded chunks to a local [adapter](../glossary.md). Probe and ordinary demux test the package/WASM parser. `decodeFrames()` and `seek()` additionally test the current browser's [WebCodecs](../glossary.md) decoder and this adapter's raster/digest path.

This distinction is the page's central contract. A parser result must not be rejected merely because the browser lacks a decoder, while a pixel result must not be presented as package-only work. The page also specifies how to interpret the three fixture-specific ISO BMFF sample-table fast paths, current packet and metadata comparisons, applicability routing, and resource cleanup before later code-cleanup agents change any implementation.

### Probe and normalized metadata

Probe loads one input, requests both `getMediaInfo()` and `getAVStreams()`, normalizes the result, and then conditionally supplements MPEG-TS AAC fields from the source bytes. [src/engines/web-demuxer/adapter.ts:733-738](../../src/engines/web-demuxer/adapter.ts#L733-L738)

Container normalization splits FFmpeg's comma-separated format family. The adapter uses the input suffix only to break the Matroska/WebM and MOV/MP4 family ties; it otherwise recognizes TS, AVI, FLV, ASF, FLAC, MP3, Ogg, and WAV before falling back to the first reported name. [src/engines/web-demuxer/adapter.ts:206-254](../../src/engines/web-demuxer/adapter.ts#L206-L254)

Track typing prefers `codec_type_string` and falls back to numeric FFmpeg media types. Codec normalization maps FFmpeg names for H.264, H.265/HEVC, VP8, VP9, AV1 decoder aliases, AAC, Opus, MP3, FLAC, and Vorbis to suite tokens; an unknown name is retained lowercased. It does not itself receive sample-entry strings such as `avc1` or Matroska codec ids such as `V_MPEG4/ISO/AVC` on this normal package path. [src/engines/web-demuxer/adapter.ts:172-204](../../src/engines/web-demuxer/adapter.ts#L172-L204) [src/engines/web-demuxer/adapter.ts:257-290](../../src/engines/web-demuxer/adapter.ts#L257-L290)

Video metadata carries width, height, reported rotation, positive bitrate, language, and fps parsed from `avg_frame_rate` with `r_frame_rate` as fallback. Audio carries sample rate, channels, bitrate, and language. Duration is accepted only when finite and positive. Tags are limited to chapter count and the first nonempty stream occurrence of title, artist, album, comment, encoder, or date. [src/engines/web-demuxer/adapter.ts:293-321](../../src/engines/web-demuxer/adapter.ts#L293-L321) [src/engines/web-demuxer/adapter.ts:497-535](../../src/engines/web-demuxer/adapter.ts#L497-L535) [src/engines/web-demuxer/adapter.ts:538-578](../../src/engines/web-demuxer/adapter.ts#L538-L578)

The TS supplement is not a second general demuxer. It scans 188-byte packets, follows the first nonzero PAT program to one PMT, selects the first stream type `0x0f` AAC PID, strips an initial PES header, collects at most 64 KiB, and parses one ADTS header's sampling-frequency index and channel configuration. LATM AAC (`0x11`), multiple missing AAC tracks, program selection, full MPEG-4 `AudioSpecificConfig`, SBR, and Parametric Stereo are not handled. ### Normal packet demux

Outside the large-asset fast path, demux loads the input, fetches media info and stream descriptors, and constructs metadata without applying the TS AAC byte supplement used by probe. It chooses an end time one second beyond a positive reported duration, or one billion seconds when duration is unknown. [src/engines/web-demuxer/adapter.ts:764-783](../../src/engines/web-demuxer/adapter.ts#L764-L783)

For each video, audio, or subtitle stream, the adapter calls low-level `readAVPacket(0, end, mediaType, stream.index)` and drains its `ReadableStream`. Data and attachment streams are skipped. `PacketInfo.trackIndex` is the absolute upstream stream index, size is the upstream packet size, the upstream seconds timestamp is rounded to microseconds, and the 0/1 key flag becomes a boolean. The package's packet type has no DTS field, so the adapter sets `dtsUs = ptsUs`. It then sorts the combined table by PTS and track index. [src/engines/web-demuxer/adapter.ts:743-762](../../src/engines/web-demuxer/adapter.ts#L743-L762) [src/engines/web-demuxer/adapter.ts:785-828](../../src/engines/web-demuxer/adapter.ts#L785-L828) The normalized contract itself requires numeric PTS, DTS, size, track index, and keyframe for every row, leaving no representation for unknown DTS. [src/core/engine.ts:43-74](../../src/core/engine.ts#L43-L74)

This per-stream addressing is what makes the current `multitrack` claim: the adapter does not use the package convenience call that selects only a best stream. It assumes that upstream stream indices are dense and aligned with the normalized track-array order; no map from raw stream id to normalized array position is constructed. [src/engines/web-demuxer/adapter.ts:743-759](../../src/engines/web-demuxer/adapter.ts#L743-L759) [src/engines/web-demuxer/adapter.ts:791-805](../../src/engines/web-demuxer/adapter.ts#L791-L805)

On normal completion the stream closes and the adapter releases the reader lock. On any read error it also only releases the lock; it does not call `cancel()`. A TS input whose message loosely matches reader/AVPacketReader plus null/create/failed/nullptr is translated to a local `NotApplicableError`. Every other failure, including every other TS failure, is rethrown. [src/engines/web-demuxer/adapter.ts:124-155](../../src/engines/web-demuxer/adapter.ts#L124-L155) [src/engines/web-demuxer/adapter.ts:792-823](../../src/engines/web-demuxer/adapter.ts#L792-L823) The exact package bundle's stream cancel algorithm posts `StopReadAVPacket`; releasing a lock is not that cancellation signal. ### Fixture-specific progressive ISO BMFF sample-table path

Demux bypasses web-demuxer entirely for three unmutated ids: `h264_1080p_30s.mp4`, `huge_h264_1080p_600s.mov`, and `massive_h264_1080p_2h.mp4`. This is an adapter-local optimization for large progressive [ISO BMFF](../glossary.md) fixtures, not an upstream web-demuxer API path. [src/engines/web-demuxer/adapter.ts:764-767](../../src/engines/web-demuxer/adapter.ts#L764-L767) [src/engines/web-demuxer/mp4-sample-table.ts:1-23](../../src/engines/web-demuxer/mp4-sample-table.ts#L1-L23) [src/engines/web-demuxer/mp4-sample-table.ts:39-60](../../src/engines/web-demuxer/mp4-sample-table.ts#L39-L60)

The helper range-reads an initial 64 KiB and then top-level headers until it locates `moov`. It caps top-level boxes at 32, `moov` at 128 MiB, and packet rows at two million. It rejects HTTP failures, an obviously unhonored oversized range response, oversized/missing `moov`, missing required table boxes, truncated `stsz`, unsafe 64-bit box sizes, and an empty packet result. It never reads `mdat`. [src/engines/web-demuxer/mp4-sample-table.ts:20-23](../../src/engines/web-demuxer/mp4-sample-table.ts#L20-L23) [src/engines/web-demuxer/mp4-sample-table.ts:68-105](../../src/engines/web-demuxer/mp4-sample-table.ts#L68-L105) [src/engines/web-demuxer/mp4-sample-table.ts:108-137](../../src/engines/web-demuxer/mp4-sample-table.ts#L108-L137) [src/engines/web-demuxer/mp4-sample-table.ts:308-327](../../src/engines/web-demuxer/mp4-sample-table.ts#L308-L327) [src/engines/web-demuxer/mp4-sample-table.ts:408-414](../../src/engines/web-demuxer/mp4-sample-table.ts#L408-L414)

Only `vide` and `soun` tracks are retained and compactly renumbered. For each, `mdhd` supplies a timescale; `stsz` supplies byte sizes; expanded `stts` deltas produce DTS; optional `ctts` offsets produce PTS; and optional `stss` supplies sync-sample flags, with every sample treated as sync when `stss` is absent. [src/engines/web-demuxer/mp4-sample-table.ts:139-189](../../src/engines/web-demuxer/mp4-sample-table.ts#L139-L189) This division of responsibilities matches the standard sample-table model summarized in Apple's [sample atoms documentation](https://developer.apple.com/documentation/quicktime-file-format/sample_atoms), but the helper does not validate chunk/sample placement through `stsc` plus `stco`/`co64` or the existence of corresponding media bytes.

Metadata is intentionally thin. Movie duration is `mvhd` duration when available, otherwise maximum parsed track duration. The first `stsd` entry maps `avc1`/`avc3` to H.264, `hvc1`/`hev1` to HEVC, and `mp4a` to AAC. Video width/height come from fixed sample-entry offsets and fps is sample count divided by summed media duration; audio channel count and sample rate come from fixed offsets. The helper does not apply edit lists, track matrices/rotation, language, bitrate, tags, multiple sample descriptions, fragmented `moof`/`trun` data, subtitle tracks, or data tracks. ### WebCodecs decode, raster, and digest path

`decodeFrames()` first requires global `VideoDecoder` and `EncodedVideoChunk` constructors. It loads the input, asks the package for the primary video decoder configuration, probes a trimmed copy with `VideoDecoder.isConfigSupported()`, and configures the decoder with the full package result. The support copy carries codec, coded dimensions, and description; other package fields are omitted from the support query. [src/engines/web-demuxer/adapter.ts:598-603](../../src/engines/web-demuxer/adapter.ts#L598-L603) [src/engines/web-demuxer/adapter.ts:848-858](../../src/engines/web-demuxer/adapter.ts#L848-L858) [src/engines/web-demuxer/adapter.ts:1080-1090](../../src/engines/web-demuxer/adapter.ts#L1080-L1090) WebCodecs makes codec support user-agent dependent and recommends checking `isConfigSupported()` before configure. [W3C WebCodecs](https://www.w3.org/TR/webcodecs/)

The adapter reads the package's primary video `EncodedVideoChunk` stream and pipelines chunks into the decoder. With finite `maxFrames = N`, it submits at most `N + 16` chunks, retains at most that many output frames, sorts retained frames by presentation timestamp, and emits the first N. Excess callback frames close immediately. A decoder callback error is thrown only when it produced zero frames; if at least one frame was collected, the error is ignored and a shorter/partial sink can be returned. [src/engines/web-demuxer/adapter.ts:860-927](../../src/engines/web-demuxer/adapter.ts#L860-L927)

The encoded reader is canceled and unlocked in `finally`, the decoder is closed, and every retained `VideoFrame` is closed after rasterization. If read, decode, or flush throws, the decode path also closes already-collected frames before rethrowing. [src/engines/web-demuxer/adapter.ts:882-919](../../src/engines/web-demuxer/adapter.ts#L882-L919) [src/engines/web-demuxer/adapter.ts:929-945](../../src/engines/web-demuxer/adapter.ts#L929-L945) WebCodecs identifies `VideoFrame` objects as holders of scarce codec resources and recommends prompt release; the current close calls satisfy that rule on this path. [W3C WebCodecs resource model](https://www.w3.org/TR/webcodecs/#resource-reclamation)

Rasterization uses display dimensions. For an uncropped frame whose coded and visible dimensions equal its display size, it first attempts `VideoFrame.copyTo(..., {format: "RGBA"})`. Otherwise, or when copy fails, it creates an `OffscreenCanvas` or DOM canvas, draws the frame, and reads `ImageData`. Missing canvas contexts and zero-size frames are errors. [src/engines/web-demuxer/raster.ts:21-49](../../src/engines/web-demuxer/raster.ts#L21-L49) [src/engines/web-demuxer/raster.ts:51-100](../../src/engines/web-demuxer/raster.ts#L51-L100)

Each result records index, PTS, dimensions, and SHA-256 of a tight RGBA copy. Web Crypto absence is an error. `RetainingFrameSink` stores both the digest and the full `ImageData` for every emitted frame so SSIM/PSNR can call `getPixels(i)` later; a full unbounded decode therefore retains roughly width × height × 4 bytes per frame in addition to transient decoder/canvas resources. [src/engines/web-demuxer/digest.ts:31-44](../../src/engines/web-demuxer/digest.ts#L31-L44) [src/engines/web-demuxer/digest.ts:46-73](../../src/engines/web-demuxer/digest.ts#L46-L73) [src/engines/web-demuxer/adapter.ts:581-596](../../src/engines/web-demuxer/adapter.ts#L581-L596)

### Seek path

`seek()` has the same WebCodecs presence and configuration preflight. It clamps negative input to zero and, when duration is known, clamps past-EOF input to one millisecond before duration. It starts a package `read("video", target, target + 0.75s, AV_SEEK_FLAG_BACKWARD)` stream, decodes every returned chunk, cancels/unlocks the reader, flushes, and closes the decoder. [src/engines/web-demuxer/adapter.ts:957-1019](../../src/engines/web-demuxer/adapter.ts#L957-L1019)

The package's backward flag chooses a preceding random-access start, but the adapter then decodes forward. It selects the last callback-observed frame at or before the clamped target, or the first observed frame if none is at or before it. The `decoded` array is not sorted before that selection, so “last” is decoder callback order rather than explicitly maximum PTS. A callback error is ignored whenever any landed frame exists. [src/engines/web-demuxer/adapter.ts:977-987](../../src/engines/web-demuxer/adapter.ts#L977-L987) [src/engines/web-demuxer/adapter.ts:1021-1039](../../src/engines/web-demuxer/adapter.ts#L1021-L1039)

The returned frame is rasterized and digested with index zero; all decoded frames close in the landing-result `finally`. There is one exceptional leak path: if read/decode/flush throws after output callbacks have appended frames, control exits through the earlier catch before reaching that landing-result cleanup, and the catch closes the decoder but not the accumulated frames. [src/engines/web-demuxer/adapter.ts:989-1019](../../src/engines/web-demuxer/adapter.ts#L989-L1019) [src/engines/web-demuxer/adapter.ts:1021-1040](../../src/engines/web-demuxer/adapter.ts#L1021-L1040)

The shared seek oracle resolves the expected keyframe or nearest real video PTS from golden packets/frames and compares the returned `landedPtsUs` within the scenario tolerance; the digest is deliberately not the seek hard gate. B-frame, VFR, exact-keyframe, negative, zero, past-EOF, repeated, and backward-seek cases are registered. ## Target design and known gaps

### Target design

#### 1. Make support operation- and tuple-specific

Retain the flat gate only as a cheap first pass. Add an adapter-owned decision over:

`operation × actual container × selected track type/index × codec/configuration × protection × browser API/configuration × fast-path eligibility`.

Probe and packet demux should be marked parser-independent per operation. Decode and seek must pass the exact package-generated `VideoDecoderConfig` through browser applicability. A valid tuple rejected by the installed package or adapter—such as current TS packet streaming—should throw reason-coded `NotApplicableError` and become `NA_ENGINE`. Missing `VideoDecoder`, rejected `isConfigSupported()`, absent raster primitives, or unavailable Web Crypto should use a distinct browser-applicability error mapped to `NA_BROWSER`. A positive preflight followed by corrupt chunks, wrong landing, decoder failure, or broken cleanup remains a genuine defect, not NA.

This change removes combinatorial unsupported tuples from FAIL/ERROR without hiding applicable defects. In particular, the PTS-wraparound 240-fps case must not be converted to NA: TS probe is declared and works on ordinary TS, so the disabled cell should be re-enabled as FAIL until fps derivation is fixed, then PASS. The hand-kept disabled list should shrink only when a cell becomes a real verdict or a reasoned runtime NA. [src/core/disabled-cells.ts:95-103](../../src/core/disabled-cells.ts#L95-L103)

#### 2. Introduce representation-aware oracle verdicts

Extend `OracleOutcome` and `ResultStatus` with the three-way PASS / DIFF / FAIL contract. For packet observation:

- PASS means the scenario's semantic packet/timeline requirements and any explicitly demanded representation identity hold.
- DIFF means the stream is valid and semantically equivalent, but framing, parameter-set placement, grouping, or another permitted representation differs from the ffmpeg-baked golden.
- FAIL means invalid access units, lost/altered essence, wrong timestamps beyond tolerance, a false random-access boundary, missing tracks, or corrupt/undecodable content.

The present exact size/keyframe comparator is unfair as a universal oracle. [Annex B](../glossary.md) and length-prefixed [AVCC](../glossary.md) encode NAL boundaries differently; SPS/PPS/VPS can be in-band or carried in decoder configuration; and demuxers can group legal NAL units differently. W3C's [AVC registration](https://www.w3.org/TR/webcodecs-avc-codec-registration/) and [HEVC registration](https://www.w3.org/TR/webcodecs-hevc-codec-registration/) explicitly distinguish Annex B from canonical length-prefixed chunks and the corresponding location of parameter sets. Matroska also permits [lacing multiple frames into one Block](https://www.rfc-editor.org/rfc/rfc9559.html#section-10.3), so byte size and one-to-one grouping are container representations, not universal content truth.

Extend packet evidence with optional DTS, duration, codec configuration, framing, access-unit/NAL grouping, and a payload digest or independently decoded essence digest. When evidence is insufficient to distinguish valid DIFF from wrong FAIL, return an explicit oracle applicability gap rather than guessing. Exact byte size/keyframe equality remains appropriate only for scenarios that explicitly promise representation identity.

#### 3. Canonicalize metadata semantically

The shared `golden-metadata` layer must canonicalize both candidate and golden codecs: `avc1`/`avc3` and `V_MPEG4/ISO/AVC` → `h264`; `hev1`/`hvc1` → `hevc`; and `mp4a` → `aac`. The existing reference-reimport structure comparison already canonicalizes both known codec tokens, while `golden-metadata` does not; reuse that vocabulary rather than maintaining divergent comparators. [src/core/oracles.ts:341-371](../../src/core/oracles.ts#L341-L371) [src/core/oracles.ts:785-811](../../src/core/oracles.ts#L785-L811) Matroska's [codec mappings](https://www.matroska.org/technical/codec_specs.html) provide the container-id side of this equivalence; RFC 6381 defines the [ISO family codec parameter vocabulary](https://www.rfc-editor.org/rfc/rfc6381.html).

Match tracks by media type plus stable identifying attributes, not raw array index. Treat HE-AAC/SBR core-rate versus rendered 2× rate and Parametric Stereo mono-core versus stereo-render reports as equivalent. RFC 6416's [SBR and HE-AAC v2 examples](https://www.rfc-editor.org/rfc/rfc6416.html#section-7.4.1.5) explicitly show a 24 kHz core with 48 kHz SBR output and a mono core with stereo PS output. The adapter's ADTS-only TS supplement cannot infer those distinctions and must attach provenance such as `adts-core` rather than forcing an exact rendered value.

Represent fps as nominal/average/observed plus a tolerance model. Band rational NTSC rates such as 30000/1001 and tolerate VFR summary differences instead of applying one universal absolute delta. Duration tolerance must account for edit-list presentation, codec priming, and timebase quantization. The ISO standard describes ISO BMFF as containing timing and presentation structure, not just a raw media-duration scalar. [ISO/IEC 14496-12:2026](https://www.iso.org/standard/85596.html)

#### 4. Make decode and seek comparisons temporal

Keep the source's neutral in-browser WebCodecs decode as the perceptual reference; it is fair because it is independent of every competing engine. Replace array-index pairing with presentation-time matching after the declared fps/transform policy, record maximum pairing delta and coverage, and treat duplicate/drop/VFR cases explicitly. An fps or frame-count change must compare a candidate frame with the source image at the corresponding time, not frame `i`.

Separate media validity from browser reference applicability. For output-producing engines, valid output that the neutral browser cannot decode should not automatically be content FAIL; it should preserve other semantic evidence and mark the visual check `NA_BROWSER` or DIFF under the shared composition policy. For current web-demuxer decode/seek, an exact decoder configuration unavailable in the browser is directly `NA_BROWSER`, while malformed package configuration after a claimed-supported tuple is ERROR/FAIL.

Seek should sort decoded candidates by PTS, select the maximum real PTS at or before the target (or the scenario-defined nearest/keyframe rule), and prove that the chosen PTS exists in demux/golden timing. Replace the fixed 0.75-second read window with an end condition tied to landing evidence and GOP progress. Preserve exact behavior for negative, zero, past-EOF, repeated, backward, B-frame, Matroska/WebM Cues, and VFR cases.

#### 5. Make backend provenance and ISO BMFF semantics explicit

Either run the pinned package for every ordinary demux cell or expose the sample-table helper as a distinct backend/config in reports. One engine id must not silently mean “FFmpeg/WASM packet stream” for most files and “custom `moov` parser” for three large files.

If retained, the helper must:

1. validate `stsc` plus `stco`/`co64` sample placement and referenced file ranges, or explicitly promise table observation only;
2. apply edit lists to presentation timing/duration and track matrices to display metadata;
3. support or reject multiple sample descriptions, fragmented files, subtitles/data, and unsupported handler/sample-entry forms with reason-coded applicability;
4. preserve a stable map from container track id to normalized track index;
5. stream or run-length-process `stts`/`ctts` instead of expanding several duplicate arrays; and
6. report backend, bytes/ranges read, `moov` size, packet count, and omitted evidence.

#### 6. Make readiness, cancellation, and cleanup observable

`init()` must await a public or adapter-mediated package readiness promise if cold WASM work is intended to be excluded from operation timing; otherwise label the first-operation measurement as including worker/WASM startup. Never claim compile placement based only on construction.

Thread an `AbortSignal` from runner timeout/cancel through load, packet readers, decode, seek, range fetches, and raster work. On abort, cancel active streams, close every `VideoFrame`, terminate the worker, await operation settlement, and publish no terminal result until a cleanup barrier completes. The Streams Standard defines [readable-stream cancellation](https://streams.spec.whatwg.org/#rs-cancel); releasing a reader lock is not a substitute.

Bound memory independently for packet rows, table expansion, live decoder frames, and retained pixels. Let perceptual oracles request only temporally sampled pixel frames or use a spillable pixel store rather than retaining full RGBA for an unbounded decode. Close seek frames in the exceptional read/flush path. Report cleanup failure instead of swallowing both `destroy()` and runner disposal exceptions.

#### 7. Grade multi-file robustness as coverage

Preserve each file's verdict and use a partial/coverage grade for mixed robustness results. “File 01 passes; files 02 and 03 fail” is valuable robustness evidence, not a cell-level harness ERROR. A true construction/init/harness fault can remain ERROR per file; mixed valid robustness observations should report passed/admissible/total and the failing bytes without erasing the successful signal.

#### 8. Adapter conformance suite

Add focused tests before broadening capabilities or deleting the disabled row:

1. package, lock integrity, reported id, full-versus-mini export, same-origin WASM URL, and cold-readiness timing;
2. registration, fresh-cell construction, repeated `init()`, repeated loads, and exactly-once worker teardown;
3. every declared container/codec for probe and demux, plus undeclared formats, audio-only files, missing primary video, protected tracks, and TS probe-versus-demux separation;
4. multitrack inputs with sparse/nonzero upstream indices, duplicate media types, subtitles, data, attachments, and track-order changes;
5. MPEG-TS PAT/PMT variants, multiple programs/AAC tracks, ADTS versus LATM, HE-AAC/SBR/PS, PTS wraparound, discontinuity, and malformed tables;
6. ordinary and fast-path parity for the same small ISO BMFF file, plus edit lists, priming, VFR/NTSC, B-frame `ctts`, multiple `stsd` entries, missing `stss`, fragmented media, huge/truncated boxes, unhonored ranges, and `moov`/`mdat` inconsistency;
7. AVCC versus Annex B, in-band versus out-of-band SPS/PPS/VPS, alternate NAL grouping, Matroska lacing, unknown DTS, and true keyframe/random-access semantics, expecting representation-only cases to become DIFF;
8. WebCodecs absence and unsupported exact configs as `NA_BROWSER`, package tuple rejection as `NA_ENGINE`, malformed chunks as FAIL/ERROR, and no capability-bypass leakage;
9. decode reorder depths above 16, partial decoder errors, zero/one/N frame limits, VFR/CFR frame-count changes, timestamp-based SSIM pairing, copyTo versus canvas raster parity, rotation/crop/color/alpha, and Web Crypto absence;
10. seek at exact keyframes, mid-GOP B-frames, VFR times, before zero, after EOF, repeated/backward calls, read windows longer than 0.75 seconds, callback reordering, and decode failure after frames were emitted;
11. cancel/timeout during WASM readiness, URL/File load, packet read, range fetch, decode, flush, raster, and digest, asserting no live reader, worker, frame, listener, or post-result work; and
12. machine-readable persistence of backend/config and PASS, DIFF, FAIL, NA_ENGINE, NA_BROWSER, NA_ASSET, ERROR, SKIPPED, and partial robustness coverage.

#### Decode and seek can accept partial or callback-order evidence

- **Current.** Decode suppresses a decoder callback error when any frame exists. Its fixed 16-frame margin is only an assumed reorder bound. Seek does not sort callback outputs before choosing a landed frame and also suppresses an error when a frame exists. [src/engines/web-demuxer/adapter.ts:860-927](../../src/engines/web-demuxer/adapter.ts#L860-L927) [src/engines/web-demuxer/adapter.ts:977-1027](../../src/engines/web-demuxer/adapter.ts#L977-L1027)
- **Consequence.** A truncated decode can be scored on surviving frames, and an unusual reorder depth/callback sequence can select the wrong first-N or seek landing. Index-based frame pairing compounds fps/frame-count changes.
- **Target.** Require declared frame coverage, surface partial decode state, pair by PTS, sort seek candidates, and use a landing condition rather than a fixed read window/reorder guess.
- **Verification.** Inject failures after one or several frames, use deep reorder and VFR streams, alter frame count/fps, and permute callback order; require deterministic temporal matches and an explicit partial/failure classification.

#### Timeout and teardown are not end-to-end cancellation

- **Current.** Runner timeout only races promises. Normal demux does not cancel a reader on exceptional exit, teardown errors are swallowed, and seek leaks accumulated frames if read/flush throws before landing cleanup. [src/core/runner.ts:655-684](../../src/core/runner.ts#L655-L684) [src/engines/web-demuxer/adapter.ts:792-823](../../src/engines/web-demuxer/adapter.ts#L792-L823) [src/engines/web-demuxer/adapter.ts:989-1040](../../src/engines/web-demuxer/adapter.ts#L989-L1040)
- **Consequence.** Work can continue after a terminal result; worker/WASM and frame resources may outlive the cell; suppressed cleanup failure makes peak-memory and isolation claims unverifiable.
- **Target.** Abort propagation, active-stream cancellation, all-path frame closure, worker termination acknowledgement, and cleanup as part of cell settlement.
- **Verification.** Cancel at every async phase and assert zero later callbacks/messages, all streams settled, every frame closed, and no worker/WASM memory growth across repeated cells.

#### Cold WASM work is not proven outside operation timing

- **Current.** `init()` constructs the package object but does not await the package's private readiness promise; `load()` performs that await. [src/engines/web-demuxer/adapter.ts:668-695](../../src/engines/web-demuxer/adapter.ts#L668-L695) [src/engines/web-demuxer/adapter.ts:714-728](../../src/engines/web-demuxer/adapter.ts#L714-L728)
- **Consequence.** The first operation may include worker/WASM startup despite comments and interface intent saying expensive setup is excluded, biasing performance comparisons.
- **Target.** Await explicit readiness in init or report startup-inclusive timing separately from warm operation timing.
- **Verification.** Instrument worker-created, WASM-fetch-start/end, runtime-ready, load-start, and operation-start events across cold and warm runs; assert the selected metric boundary.

#### Robustness coverage collapses to one terminal status

- **Current.** Per-file exhaustive details and coverage exist, but any admissible file failure collapses the cell to FAIL or ERROR. [src/core/runner.ts:1118-1179](../../src/core/runner.ts#L1118-L1179)
- **Consequence.** “Passes file 01, fails 02/03” loses its partial robustness grade in the headline, and an ERROR-only failure set can obscure successful handling of other files.
- **Target.** Preserve per-file errors, but headline mixed robustness as partial coverage rather than whole-cell ERROR; rank/report passed/admissible/total.
- **Verification.** Use a three-file group with one PASS, one semantic FAIL, and one clean unsupported NA; verify stable partial coverage and exact per-file reasons. Use a true init fault separately and retain ERROR for that file.

#### Adapter-local behavior has no focused tests

- **Current.** Repository search finds matrix scenarios and one disabled web-demuxer row, but no unit/spec file directly exercising the TS parser, sample-table helper, raster/digest path, error-name matching, or worker lifecycle.
