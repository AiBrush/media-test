# Audio DSP

> Scope: Audio-only resampling, channel mixing, gain, fades, PCM representation changes, audio throughput, container-read edges, gapless behavior, malformed-input handling, and audio metamorphic scenarios; generic runner, oracle, fixture, and engine contracts are linked rather than redefined.
> Phase-2 owner: p2_feature_audio_dsp.

## Purpose

This family asks whether an [engine](../glossary.md#engine) can transform or inspect audio without changing properties that the requested operation should preserve. Each [scenario](../glossary.md#scenario) is engine-independent: it names an input, operation, requested audio shape, capability requirements, an [oracle](../glossary.md#oracle), and metrics. The resulting engine × scenario × browser [cell](../glossary.md#cell) is useful only when correctness is strong enough to gate its performance number.

The page is the behavioral specification for later cleanup of the audio scenarios and their supporting [adapters](../glossary.md#adapter). It complements the [runner and capability-negotiation](../subsystems/runner-capability-negotiation.md), [oracle-system](../subsystems/oracle-system.md), [golden](../glossary.md#golden) and [fixture](../subsystems/golden-baking-fixtures.md), and individual [engine-adapter contract](../subsystems/engine-adapter-contract.md) pages.

## Target design and known gaps

### Target design

The target turns this family into a signal-domain conformance suite with honest applicability and representation-aware verdicts.

1. **Separate semantic validity from representation.** Each oracle emits [PASS](../glossary.md#pass), [DIFF](../glossary.md#diff), or [FAIL](../glossary.md#fail). PASS means the requested signal/container contract holds after documented normalization. DIFF means the output is valid and semantically acceptable but differs from the ffmpeg-baked [golden](../glossary.md#golden) representation. FAIL is reserved for invalid media, a wrong transform, content loss, an undecodable required output, or a tolerance breach. Acceptance: a codec alias, legal timing expression, lawful channel metadata view, or resampler-specific waveform that satisfies the quality/timing contract can never become FAIL merely for differing from the baker; the report retains the diagnostic difference.

2. **Give every conversion a two-layer oracle.** First parse WAV, AIFF/AIFC, CAF, and relevant compressed outputs without using a scored engine; assert requested container, codec/sample format, native sample rate, sample-frame count/duration, channel count and, where represented, channel layout. WAVEFORMATEXTENSIBLE exists specifically to carry valid bits and speaker-position channel masks beyond basic PCM fields, so multichannel checks must compare layout as well as count. [Microsoft, “WAVEFORMATEXTENSIBLE structure”](https://learn.microsoft.com/en-us/windows/win32/api/mmreg/ns-mmreg-waveformatextensible) Second, compare decoded audio in a neutral in-browser path. For raw PCM, use the native reader; for compressed media, demux and decode through [WebCodecs](../glossary.md#webcodecs) `AudioDecoder`/`AudioData`, whose model exposes sample rate, sample-frame count, channel count, and timestamps. [W3C, “WebCodecs” audio data model](https://www.w3.org/TR/webcodecs/#audio-data-interface) Acceptance: every conversion row produces a verdict with nonzero structural checks and a recorded decoded rate/count; no supported WAV conversion retires as `NA_ASSET` merely because the oracle lacks a reader.

3. **Match the comparator to the transform.** Exact identity/endian rows compare normalized samples bit-for-bit and record the actual intermediate representation. Format reduction declares clipping, rounding, and dither policy before claiming bit-exactness. Gain rows measure achieved gain away from silence/clipping; fade rows sample the envelope at boundaries and inside each ramp. Resampling uses duration/rate checks plus documented signal-quality or spectral tolerances because valid resamplers can select different filter engines, precision, cutoff, phase, dithering, and rematrixing options. [FFmpeg, “Audio Resampler”](https://www.ffmpeg.org/ffmpeg-resampler.html) Channel rows declare input and output speaker layouts plus an explicit matrix; ITU-R BS.775 includes a downward-mixing annex, but an engine default is not evidence that the scenario's intended matrix was used. [ITU-R, “Recommendation BS.775: Multichannel stereophonic sound system”](https://www.itu.int/rec/R-REC-BS.775/en) Acceptance: inject impulses in each source channel and tones at several frequencies; verify routing/coefficient tolerances, duration, clipping behavior, and silence preservation.

4. **Use native-rate audio evidence.** Web Audio specifies that `decodeAudioData` resamples decoded content to the `BaseAudioContext` sample rate. [W3C, `decodeAudioData`](https://www.w3.org/TR/webaudio-1.1/#dom-baseaudiocontext-decodeaudiodata) It must not be the sole source of native sample-rate or native sample-count truth. Acceptance: running on devices with 44.1 and 48 kHz default contexts yields the same oracle verdict and native measurements; the result records whether evidence came from a container PCM reader or WebCodecs decode.

5. **Make gapless comparison priming-aware.** Derive valid decoded frames from explicit container timing, packet-table priming/remainder, and presentation mapping rather than assuming raw AAC frames equal program samples. Apple's packet-table contract defines valid frames after priming and remainder, and its QuickTime guidance represents encoder delay with track structures/edit lists. [Apple, `AudioFilePacketTableInfo`](https://developer.apple.com/documentation/audiotoolbox/audiofilepackettableinfo) [Apple, “Using track structures to represent encode delay explicitly”](https://developer.apple.com/documentation/quicktime-file-format/using_track_structures_to_represent_encode_delay_explictly) Acceptance: the non-frame-aligned AAC fixture decodes to the intended presentation sample count within one native output sample, reports observed priming/remainder and rate, and plays/loops without an added leading or trailing region.

6. **Upgrade shared [golden metadata](../glossary.md#golden-metadata).** Canonicalize suite codec tokens before comparison: `avc1`/`avc3`→h264, `hev1`/`hvc1`→hevc, `V_MPEG4/ISO/AVC`→h264, and the corpus's `mp4a` AAC sample entries→aac. The registered ISO BMFF sample-entry values and Matroska CodecIDs are representation labels, not different decoded codecs. [MP4 Registration Authority, “Codecs”](https://mp4ra.org/registered-types/codecs) [Matroska, “Codec Mappings”](https://www.matroska.org/technical/codec_specs.html) Match tracks by media type and stable per-type identity rather than global array index. Treat documented [HE-AAC/SBR](../glossary.md#he-aacsbr) core versus reconstructed output-rate views (commonly base versus 2×) and HE-AAC v2 [Parametric Stereo](../glossary.md#parametric-stereo) mono-core versus stereo-output views as semantically equal; the AAC WebCodecs registration identifies audio object types 5 and 29 as HE-AAC v1/v2, and ETSI's HE-AAC transport guidance describes SBR output-rate doubling and Parametric Stereo's mono-to-stereo reconstruction. [W3C, “AAC WebCodecs Registration — fully qualified codec strings”](https://www.w3.org/TR/webcodecs-aac-codec-registration/#fully-qualified-codec-strings) [ETSI TS 102 005 V1.2.1, Annex A](https://www.etsi.org/deliver/etsi_TS/102000_102099/102005/01.02.01_60/ts_102005v010201p.pdf) Band [VFR](../glossary.md#vfr), [NTSC rate](../glossary.md#ntsc-rate), and rational-rate fps observations rather than requiring a rounded scalar match. Widen duration only when an [edit list](../glossary.md#edit-list), [priming](../glossary.md#priming), or [timebase](../glossary.md#timebase) conversion explains the delta; retain a strict band otherwise. Acceptance fixtures cover reordered audio/video tracks, every alias, HE-AAC rate/channel dual views, 30000/1001, edit-list offsets, and encoder delay.

7. **Model support as a tuple and keep runtime rejection non-failing.** Negotiate operation × input container/codec × output container/codec × transform options; until that exists, every adapter must throw [NotApplicableError](../glossary.md#notapplicableerror) when a concrete tuple cannot be honored, yielding [NA_ENGINE](../glossary.md#na_engine), not `FAIL` or `ERROR`. This includes Mediabunny's unknown-duration fade-out, Remotion parser/WebCodecs union combinations, and any runtime rate/layout restriction. Mediabunny's official conversion options expose `sampleRate`, `numberOfChannels`, `sampleFormat`, and `process`, while Remotion documents `convertMedia` as an experimental WebCodecs conversion path with MP4/WebM/WAV outputs; adapter claims must remain no broader than the exercised framework path. [Mediabunny, `ConversionAudioOptions`](https://mediabunny.dev/api/ConversionAudioOptions) [Remotion, `convertMedia()`](https://www.remotion.dev/docs/webcodecs/convert-media) Acceptance: a table-driven test exercises unsupported tuples for every adapter and observes `NA_ENGINE`; disabled-cell entries are retained only for reproducible cost/pathology exceptions, not ordinary lack of support.

8. **Define audio throughput in audio units.** Count sample frames processed at the native input or output rate and publish `sampleFramesPerSec`; if scalar samples/s is also useful, multiply by channel count and name it explicitly. Encode rows derive their numerator from duration × native rate or an encoder-produced count, never video fps. Acceptance: both encode rows have `n > 0`, positive finite samples, and a numerator matching their decoded output sample-frame count; changing channel count does not silently change the meaning of the metric.

9. **Make metamorphic work observable.** A round-trip scenario must prove that each requested leg ran, record the intermediate container/codec/rate/layout, and compare final normalized samples. An adapter that lacks the two-leg facility returns `NA_ENGINE`, not a one-leg PASS. Acceptance: deliberately bypassing the s16be intermediate makes the test fail, while a genuine endian round trip passes on all supporting adapters.

10. **Preserve robustness detail.** For a set of malformed input variants, retain each per-file outcome. If file 01 passes and 02/03 fail, report [partial coverage](../glossary.md#partial-coverage), not `ERROR` and not a collapsed full pass/fail. Acceptance: aggregation exposes passed/failed counts and file ids, while a harness exception remains `ERROR` and an unsupported combination remains `NA_ENGINE`.

### Known gaps

1. **WAV conversions usually have no correctness verdict.** **Current:** the output-metadata invariant reads MP4/WebM/AIFF but not WAV/CAF, and emits a truth-unavailable outcome. [src/core/oracles.ts:3738-3762](../../src/core/oracles.ts#L3738-L3762) **Consequence:** most supported audio conversions become `NA_ASSET`, so their DSP correctness and performance are not scored. **Target:** add RIFF/WAVE, WAVEFORMATEXTENSIBLE, and CAF structural readers, then run the neutral signal oracle described above. [Microsoft, “WAVEFORMATEXTENSIBLE structure”](https://learn.microsoft.com/en-us/windows/win32/api/mmreg/ns-mmreg-waveformatextensible) **Verification:** every supported conversion row yields PASS/DIFF/FAIL with at least container, codec/sample format, rate, channel count/layout, duration, and decoded-signal evidence.

2. **Transform notes overstate enforcement.** **Current:** all conversion rows use the same metadata property and the `bitReproducible` flag is ignored. [src/scenarios/audio-dsp/index.ts:288-317](../../src/scenarios/audio-dsp/index.ts#L288-L317) **Consequence:** wrong gain, silent fades, wrong channel coefficients, broken endian swaps, or bad PCM quantization can pass structurally—or retire as unavailable—while notes claim exactness. **Target:** attach transform-specific sample/spectral checks, using an explicit downmix matrix and declaring dither/rounding where exactness is required. FFmpeg's official resampler documentation shows that rematrixing, sample formats, dither, cutoff, and resampler selection are independent controls. [FFmpeg, “Audio Resampler”](https://www.ffmpeg.org/ffmpeg-resampler.html) **Verification:** one seeded fault per transform changes the verdict to FAIL; alternate valid resampler output within the quality contract is PASS or DIFF, never a false FAIL.

3. **Current PCM digest fallback is device-rate dependent.** **Current:** the digest and gapless paths use an unpinned `AudioContext.decodeAudioData`. [src/core/oracles.ts:3185-3205](../../src/core/oracles.ts#L3185-L3205) [src/core/oracles.ts:3457-3482](../../src/core/oracles.ts#L3457-L3482) **Consequence:** Web Audio may resample both sides to the context rate, hiding a native-rate error or changing count/hash across machines. **Target:** source native metadata/count from byte readers and decode compressed media through WebCodecs at the codec's output configuration; use Web Audio only as explicitly labeled playback evidence. [W3C, `decodeAudioData`](https://www.w3.org/TR/webaudio-1.1/#dom-baseaudiocontext-decodeaudiodata) [W3C, “WebCodecs”](https://www.w3.org/TR/webcodecs/) **Verification:** 44.1/48 kHz host contexts produce identical native-rate verdicts, while a deliberately mislabeled or wrongly resampled output fails.

4. **Metadata aliases and AAC dual views false-fail.** **Current:** `golden-metadata` compares ordered tracks and exact codec/rate/channel values, although reference re-import already has the suite codec canonicalizer. [src/core/oracles.ts:768-811](../../src/core/oracles.ts#L768-L811) [src/core/box-readers.ts:46-117](../../src/core/box-readers.ts#L46-L117) **Consequence:** a semantically equivalent tag, track order, HE-AAC/SBR core/output rate, or Parametric Stereo core/output channel view is classified as wrong. **Target:** use the canonical/type-matched/tolerant comparison in target item 6 and classify a remaining harmless representation difference as DIFF. [W3C, “AAC WebCodecs Registration”](https://www.w3.org/TR/webcodecs-aac-codec-registration/) [ETSI TS 102 005 V1.2.1, Annex A](https://www.etsi.org/deliver/etsi_TS/102000_102099/102005/01.02.01_60/ts_102005v010201p.pdf) **Verification:** a matrix of aliases, swapped track order, HE-AAC rate views, and Parametric Stereo channel views no longer yields FAIL; true media-type, rate, or channel-layout changes still fail.

5. **One boolean conflates representation with wrongness.** **Current:** oracle outcomes expose only `pass`, and the runner turns any real false into `FAIL`. [src/core/scenario.ts:208-221](../../src/core/scenario.ts#L208-L221) [src/core/runner.ts:1411-1436](../../src/core/runner.ts#L1411-L1436) **Consequence:** the report cannot distinguish a valid non-golden representation from corrupt or semantically wrong audio. **Target:** implement the PASS/DIFF/FAIL result model and retain normalized diffs as structured evidence. **Verification:** the same valid audio remuxed/tagged differently yields DIFF, a contract-equivalent normalized output yields PASS, and wrong samples or undecodable output yield FAIL.

6. **Capability declarations are too coarse for audio tuples.** **Current:** negotiation checks independent tokens; composite Remotion unions parser and converter declarations, and Mediabunny throws an ordinary error when a fade-out lacks duration. [src/core/runner.ts:112-189](../../src/core/runner.ts#L112-L189) [src/engines/remotion/adapter.ts:71-91](../../src/engines/remotion/adapter.ts#L71-L91) [src/engines/mediabunny/adapter.ts:703-725](../../src/engines/mediabunny/adapter.ts#L703-L725) **Consequence:** a cell can clear the gate although its concrete combination cannot run, then surface as `ERROR`/`FAIL` and require a hand-kept disabled cell. **Target:** add tuple-aware support or throw `NotApplicableError` at every adapter runtime boundary. **Verification:** unsupported rate/container/layout/effect combinations uniformly return `NA_ENGINE`, and removing ordinary unsupported combinations from the disabled list does not create failures.

7. **Audio encode throughput has no numerator.** **Current:** encoded-output frame count is derived only from a video track; empty samples aggregate to `n = 0` and zero. [src/core/runner.ts:1681-1723](../../src/core/runner.ts#L1681-L1723) [src/core/bench.ts:127-150](../../src/core/bench.ts#L127-L150) **Consequence:** `throughput_encode_s24` and `throughput_encode_s16be` cannot provide the headline number their declarations promise, and zero is ambiguous with measured zero. **Target:** publish an audio-specific sample-frame numerator and represent unavailable metrics as absent, not zero. **Verification:** both rows report finite positive sample-frame/s with `n` equal to measured iterations, and a missing numerator produces no summary.

8. **Endianness round trip is adapter-specific.** **Current:** `roundtrip` is outside `TranscodeAudioOptions`; the runner forwards it, but only ffmpeg.wasm implements the intermediate s16be leg. [src/core/engine.ts:148-160](../../src/core/engine.ts#L148-L160) [src/core/runner.ts:738-741](../../src/core/runner.ts#L738-L741) [src/engines/ffmpeg-wasm/adapter.ts:2219-2258](../../src/engines/ffmpeg-wasm/adapter.ts#L2219-L2258) **Consequence:** another adapter may ignore the option, perform an identity s16le transcode, and satisfy the final PCM digest without testing endian conversion. **Target:** make the two-leg operation an explicit typed contract or split it into observable dependent legs, with unsupported adapters returning `NA_ENGINE`. **Verification:** captured evidence identifies an AIFF/s16be intermediate; removing either leg fails the scenario.

9. **Gapless truth is entangled with presentation metadata and browser resampling.** **Current:** the oracle derives expected samples from golden duration, optionally infers priming from packet PTS, then compares a Web Audio decode within one output-rate sample. [src/core/oracles.ts:3061-3133](../../src/core/oracles.ts#L3061-L3133) **Consequence:** missing/rounded duration, edit-list mapping, output-rate conversion, or channel-view differences can obscure whether priming and remainder were removed correctly. **Target:** compare explicit valid-frame/priming/remainder facts at native rate and separately verify the edit-list presentation timeline. [Apple, `AudioFilePacketTableInfo`](https://developer.apple.com/documentation/audiotoolbox/audiofilepackettableinfo) [Apple, “Using track structures to represent encode delay explicitly”](https://developer.apple.com/documentation/quicktime-file-format/using_track_structures_to_represent_encode_delay_explictly) **Verification:** fixtures independently vary priming, remainder, edit-list offset, and timebase rounding; each measurement is reported and only a real program-sample loss/addition fails.

10. **Scenario prose has drifted from fixtures and behavior.** **Current:** CAF is described as missing although it is generated, and `edge_gapless_aac_decode` is a trim operation. [src/scenarios/audio-dsp/index.ts:416-445](../../src/scenarios/audio-dsp/index.ts#L416-L445) [fixtures/manifest.json:1035-1046](../../fixtures/manifest.json#L1035-L1046) [src/scenarios/audio-dsp/index.ts:509-528](../../src/scenarios/audio-dsp/index.ts#L509-L528) **Consequence:** report readers can misdiagnose an NA or misunderstand which adapter method is under test. **Target:** derive display facts from the manifest/operation fields and keep free-text notes non-normative. **Verification:** generated scenario summaries name the actual operation, existing asset, requested transform, active oracle, and any missing evidence without stale prose.
