# Transcode

> Scope: This page owns the registered transcode scenarios and their observable codec, container, temporal, spatial, audio, rendition, robustness, and scale contracts; shared runner, oracle, fixture, and adapter mechanics remain with their subsystem and engine pages.
> Phase-2 owner: p2_feature_transcode.

## Purpose

Transcode asks whether an [engine, scenario, oracle, and cell](../glossary.md) can turn decoded media into a requested encoded representation without losing the program, violating the requested output shape, or publishing performance for an invalid result. It is the broadest end-to-end feature family: demux, decode, transform, encode, and mux can all affect one verdict.

This page is the behavioral specification for later cleanup of transcode scenarios and their family-specific scoring. General execution belongs to [runner and capability negotiation](../subsystems/runner-capability-negotiation.md), generic comparisons to the [oracle system](../subsystems/oracle-system.md), and framework-specific behavior to the six [engine pages](../engines/aibrush-media.md).

### Registration and common execution shape

The family exports 84 static scenarios assembled from 22 internal groups. The root scenario catalogue inserts that array under the `transcode` family, rejects duplicate IDs across all families, and the browser app lazy-loads the same export. The reusable video builder prefixes `transcode/`, sets `op: 'transcode'`, forwards the options, constructs flat input/output container, codec, and feature requirements, and defaults to `ssim-psnr` plus `playback-smoke`. Its default metrics are wall time, realtime throughput, peak memory, decode/encode rates, and long tasks; its default quality floors are SSIM 0.99 and PSNR 40 dB. Individual scenarios replace those oracles, metrics, or thresholds when the transform changes what a sound comparison can observe. ### Family-specific oracle path

For transcodes without committed frame evidence, `ssim-psnr` decodes the candidate output and the original source through the same unscored platform helper, samples up to eight frames, prepares the source for supported spatial transforms, and compares pixels. That is a neutral reference decode by construction: the candidate engine never grades itself, and the source reference is not an ffmpeg encode. The helper prefers an inline MP4/WebM demux plus WebCodecs and falls back to a media element when the DOM is available. [src/core/oracles.ts:1758-1809](../../src/core/oracles.ts#L1758-L1809) [src/core/oracles.ts:1905-1996](../../src/core/oracles.ts#L1905-L1996) [src/engines/platform/oracle-helpers.ts:1-18](../../src/engines/platform/oracle-helpers.ts#L1-L18) [src/engines/platform/oracle-helpers.ts:108-165](../../src/engines/platform/oracle-helpers.ts#L108-L165)

The same code currently pairs source and candidate frames by array index. It treats failure to decode an otherwise-produced output, a null/empty sink, or zero frames as an oracle failure. Thus a correct fps/frame-count transform can be mispaired, and a valid output outside the reference decoder's container/codec reach can be labeled `FAIL` rather than separating output validity from reference decoder applicability. On the neutral source-reference path, mean SSIM alone gates the result; PSNR is computed but advisory because the independent canvas resampler is not identical to the candidate's, so a declared `psnrMinDb` does not affect that verdict. [src/core/oracles.ts:1776-1804](../../src/core/oracles.ts#L1776-L1804) [src/core/oracles.ts:1933-1996](../../src/core/oracles.ts#L1933-L1996)

The output-metadata invariant uses an independent byte reader for ISO BMFF and WebM-family output (plus a direct AIFF parser), treats MP4/MOV and WebM/MKV as families, compares duration, selects tracks by media type and requested codec compatibility, and checks known dimensions, fps, sample rate, and channels. Unknown fields are skipped; unsupported reader coverage is routed through a `golden absent` marker to `NA_ASSET`. [src/core/oracles.ts:3738-3820](../../src/core/oracles.ts#L3738-L3820) [src/core/oracles.ts:3889-3940](../../src/core/oracles.ts#L3889-L3940) [src/core/box-readers.ts:1-16](../../src/core/box-readers.ts#L1-L16) [src/core/box-readers.ts:46-82](../../src/core/box-readers.ts#L46-L82)

Every oracle outcome is currently boolean. The runner collapses the first real non-pass to `FAIL`, emits `PASS` only when no real failure remains, and starts benchmarking only after that binary correctness gate. There is no implemented `DIFF` verdict for a valid representation that differs from reference evidence. - **Stable executable specification.** A transcode scenario has a family-qualified ID, operation, input, options, requirements, one or more oracles, and metrics; definition rejects a missing family separator, operation requirement, or oracle. ## Target design and known gaps

### Target design

1. **Use three-way oracle verdicts.** Each transcode observation must be `PASS`, `DIFF`, or `FAIL`. `PASS` means the requested semantics and structure satisfy the documented normalization/tolerances. `DIFF` means a valid rendition differs from the ffmpeg-baked golden or other reference only in legal representation—for example AVC sample-entry choice, Annex B versus AVCC length-prefixed AVC, encoder-chosen GOP/packet grouping, or equivalent timing expression. `FAIL` is reserved for invalid output, lost content, wrong transform/track, unusable required playback, or an exceeded semantic tolerance. The AVC WebCodecs registration explicitly distinguishes Annex B chunks from AVCDecoderConfigurationRecord-backed `avc` chunks, while ISO BMFF permits structured sample entries; those legal forms must not be collapsed into wrongness. ([W3C AVC codec registration](https://www.w3.org/TR/webcodecs-avc-codec-registration/), [ISO/IEC 14496-12:2022](https://www.iso.org/standard/83102.html)) Acceptance: a valid output with alternate legal framing is `DIFF`; corrupt NAL data, missing requested media, or an unplayable output in a required supported environment is `FAIL`.

2. **Keep the neutral source reference and pair on the media timeline.** Continue decoding both source and candidate through the unscored platform instrument; do not replace it with a scored engine or with an ffmpeg encode. Pair output frames by presentation-time windows derived from `ptsUs` and duration, not by array index. For output time *t*, compare the source frame whose presentation interval contains *t*; where rate conversion creates a boundary ambiguity, use the nearest source presentation time inside an explicit half-cadence window and report unmatched intervals. WebCodecs defines frame timestamps/durations in microseconds, and FFmpeg's fps filter documents that CFR conversion may drop or duplicate frames. ([WebCodecs `VideoFrame` interface](https://www.w3.org/TR/webcodecs/#videoframe-interface), [FFmpeg `fps` filter](https://ffmpeg.org/ffmpeg-filters.html#fps)) Acceptance: 30→15, 30→60, VFR→CFR, 1 fps, and 240 fps fixtures compare the same presentation instants without relying on equal frame counts.

3. **Separate output validity from reference decoder applicability.** First validate authored bytes, container/track structure, timestamps, requested codec and transform metadata, and any independent parser/decoder evidence. Separately ask whether the current browser reference path can configure and decode that exact codec configuration. WebCodecs support is explicitly configuration- and user-agent-dependent through `isConfigSupported`; a reference decoder miss therefore becomes oracle-unavailable/`NA_BROWSER`, not evidence that structurally valid output is wrong. ([WebCodecs configuration support](https://www.w3.org/TR/webcodecs/#dom-videoencoder-isconfigsupported), [WebCodecs codec registry](https://www.w3.org/TR/webcodecs-codec-registry/)) Acceptance: a valid candidate outside the helper's demux/codec reach retains its structural verdict and records SSIM as unavailable; malformed bytes that a supported configuration cannot decode remain `FAIL`.

4. **Make adapter applicability tuple-aware at runtime.** Preserve the lightweight capability gate, but require every adapter to check the concrete operation × input container/codec × output container/codec × dimensions/rate × transform tuple before or at framework invocation. A known unsupported tuple throws `NotApplicableError` and becomes `NA_ENGINE`; a browser configuration miss established by `isConfigSupported` becomes `NA_BROWSER`; an unexpected framework defect remains `ERROR`. Mediabunny exposes conversion controls and explicit encode capability probes, while Remotion documents a narrower `convertMedia` surface; adapters must translate those official boundaries rather than over-claim a flat codec set. ([Mediabunny conversion guide](https://mediabunny.dev/guide/converting-media-files), [Mediabunny `ConversionVideoOptions`](https://mediabunny.dev/api/ConversionVideoOptions), [Remotion `convertMedia()`](https://www.remotion.dev/docs/webcodecs/convert-media)) Acceptance: unsupported codec/container/rate/track combinations never arrive as `FAIL` or `ERROR`, and each removed disabled-cell rule is replaced by a reproducible tuple check or a documented performance budget policy.

5. **Make transform oracles effect-aware.** Add reference transforms for 90/180/270-degree rotation, display-matrix normalization, BT.709↔BT.2020 conversion, PQ-to-SDR tone mapping, depth conversion, alpha preservation, and requested crop/pad/flip. Validate both pixels and authored signaling; metadata/playback alone cannot prove that a visual transform occurred. BT.709 and BT.2020 define different production parameter sets, so a color conversion requires explicit transfer, matrix, primaries, range, and bit-depth observations rather than a codec-only pass. ([ITU-R BT.709-6](https://www.itu.int/rec/R-REC-BT.709-6-201506-I/en), [ITU-R BT.2020-2](https://www.itu.int/rec/r-rec-bt.2020-2-201510-i/en)) Acceptance: an adapter that ignores a requested rotate/colorspace/tonemap/depth knob fails the matching row even if the file plays and has the right codec.

6. **Compare cadence and duration as rational timeline properties.** Represent requested and observed frame rates as rationals where available, band VFR observations rather than forcing one exact scalar, and explicitly accept NTSC rates such as 30000/1001 near their rounded display values. Duration tolerances must account for timebase rounding, edit lists, frame duration at the tail, and audio priming without hiding real truncation. ISO BMFF defines the presentation timeline container, while FFmpeg exposes rational rate constants and explicit CFR drop/duplicate behavior. ([ISO/IEC 14496-12:2022](https://www.iso.org/standard/83102.html), [FFmpeg video rate filters](https://ffmpeg.org/ffmpeg-filters.html#Video-rate-filters)) Acceptance: NTSC/VFR inputs do not fail because of integer formatting, but a missing presentation interval outside the documented band does.

7. **Score audio content and priming explicitly.** Add a decoded-PCM oracle for lossless targets and a documented perceptual/error metric for lossy audio; keep codec/container/channel/sample-rate checks as structural gates. Model AAC priming/remainder padding and ISO BMFF edit-list trimming, and model Opus pre-skip/end trimming from its granule timeline. Apple's AAC guidance documents priming and remainder frames; RFC 7845 defines Opus pre-skip and end trimming. ([Apple, “Background AAC encoding”](https://developer.apple.com/documentation/quicktime-file-format/background_aac_encoding), [RFC 7845, Ogg Opus](https://www.rfc-editor.org/rfc/rfc7845.html)) Acceptance: FLAC/PCM targets prove decoded sample equality after declared trimming, AAC/Opus rows compare the intended program interval, and excess/lost samples beyond the model fail.

8. **Treat ABR output as a switchable set, not four unrelated files.** Keep per-rendition codec, dimensions, validity, and quality checks; add bitrate bands, common presentation duration/timebase, aligned random-access points/segments, and a manifest or explicit rendition-set description where streaming output is claimed. DASH-IF requires time-aligned representations and aligned segment boundaries for switching. ([DASH-IF interoperability guidelines, adaptation-set constraints](https://dashif.org/docs/DASH-IF-IOP-v4.2-clean.htm)) Acceptance: all four renditions are independently valid and cross-rendition switches at declared boundaries produce no timeline gap/overlap; a mere four-file count is insufficient.

9. **Gate metrics on valid correctness evidence.** SSIM and PSNR remain full-reference diagnostics, with the original SSIM work defining structural comparison and ITU-T J.340 explicitly compensating PSNR for constant temporal/spatial shift. ([Wang et al., “Image Quality Assessment: From Error Visibility to Structural Similarity”](https://doi.org/10.1109/TIP.2003.819861), [ITU-T J.340](https://www.itu.int/rec/T-REC-J.340/en)) Benchmark admission is limited to `PASS` and explicitly non-disqualifying `DIFF`; `FAIL`, missing mandatory evidence, or reference-applicability uncertainty cannot publish a competitive number. Count output frames and processed timestamps directly for cadence-changing transcodes instead of multiplying source nominal fps by duration. Every threshold must say whether it gates or is advisory; do not expose a `psnrMinDb` acceptance threshold on a path that ignores it. Acceptance: every published rate names its measured numerator/denominator and associated verdict, and changing a gating threshold changes the tested verdict.

10. **Make metamorphic composition real and preserve partial coverage.** Extend the scenario DSL with an explicit output binding so the second round-trip leg consumes the first result. For exhaustive input variants, retain every file verdict and report partial coverage when some valid inputs pass and others fail; do not relabel ordinary unsupported tuples or mixed robustness as `ERROR`. Acceptance: corrupting leg one changes leg two's source, and a 1/3 pass reports `partial coverage` with all filenames and denominator.

### Known gaps

1. **Binary verdict collapse.** **Current:** `OracleOutcome` is boolean and the first real false outcome collapses the cell to `FAIL`; `DIFF` does not exist. [src/core/scenario.ts:208-221](../../src/core/scenario.ts#L208-L221) [src/core/runner.ts:1411-1447](../../src/core/runner.ts#L1411-L1447) **Consequence:** a legal representation difference cannot be distinguished from truly wrong output. **Target:** implement the three-way model above, including Annex B/AVC configuration-record and ISO BMFF representation diagnostics described by the [W3C AVC registration](https://www.w3.org/TR/webcodecs-avc-codec-registration/). **Verification:** fixtures that differ only by legal AVC framing/GOP/container organization yield `DIFF`; corrupted payloads yield `FAIL`.

2. **Index-based quality pairing.** **Current:** both committed-golden and source-reference comparisons pair `frames[i]`, and fps rows omit SSIM to avoid known mispairing. [src/core/oracles.ts:1811-1843](../../src/core/oracles.ts#L1811-L1843) [src/core/oracles.ts:1933-1968](../../src/core/oracles.ts#L1933-L1968) [src/scenarios/transcode/index.ts:590-627](../../src/scenarios/transcode/index.ts#L590-L627) **Consequence:** fps/frame-count changes can false-fail, while the affected scenarios lose pixel-quality coverage entirely. **Target:** pair by timestamp/duration windows using WebCodecs' microsecond timing semantics and account for legitimate CFR drops/duplicates documented by the [FFmpeg fps filter](https://ffmpeg.org/ffmpeg-filters.html#fps). **Verification:** temporal ramps and unique-frame fixtures identify the correct source instant at 15, 30, 60, VFR, 1, and 240 fps.

3. **Reference decoder conflated with output validity.** **Current:** any platform decode throw, null sink, or zero decoded frames is a false oracle outcome and therefore usually `FAIL`. [src/core/oracles.ts:1776-1804](../../src/core/oracles.ts#L1776-L1804) **Consequence:** valid-but-reference-undecodable output is blamed on the candidate, especially for container variants or codec configurations outside the inline helper/browser. **Target:** use structural validity first and a separate `NA_BROWSER` reference-applicability result based on WebCodecs [`isConfigSupported`](https://www.w3.org/TR/webcodecs/#dom-videodecoder-isconfigsupported). **Verification:** an independently valid unsupported configuration reports quality unavailable without changing validity; the same bytes with a supported but broken sample stream fail.

4. **Coarse capability combinations and manual skips.** **Current:** negotiation checks atomic lists and feature tokens, while concrete tuple failures are discovered later; some Mediabunny/Remotion paths and Remotion Media Parser's defensive transcode stub still throw plain errors, and seven transcode cells are hand-disabled. [src/core/runner.ts:130-189](../../src/core/runner.ts#L130-L189) [src/engines/mediabunny/adapter.ts:656-663](../../src/engines/mediabunny/adapter.ts#L656-L663) [src/engines/remotion-webcodecs/adapter.ts:485-515](../../src/engines/remotion-webcodecs/adapter.ts#L485-L515) [src/engines/remotion-media-parser/adapter.ts:500-509](../../src/engines/remotion-media-parser/adapter.ts#L500-L509) [src/core/disabled-cells.ts:36-66](../../src/core/disabled-cells.ts#L36-L66) [src/core/disabled-cells.ts:179-189](../../src/core/disabled-cells.ts#L179-L189) **Consequence:** combinatorial-unsupported requests can leak into `ERROR`/`FAIL`, while stale disabled cells suppress newly supported paths. **Target:** use each framework's documented capability probe/configuration surface—such as [Mediabunny `canEncodeVideo`](https://mediabunny.dev/api/canEncodeVideo) and WebCodecs configuration queries—to throw `NotApplicableError` for runtime engine limits, including defensive undeclared-operation stubs if reached, and `NA_BROWSER` for browser limits. **Verification:** a tuple matrix asserts status and error class before removing each corresponding skip entry.

5. **Transform presence is stronger than transform proof.** **Current:** rotation and color/tone-map rows often check only output metadata/duration/playback; the reference preparation does not implement rotation or color conversion. [src/scenarios/transcode/index.ts:629-689](../../src/scenarios/transcode/index.ts#L629-L689) [src/scenarios/transcode/index.ts:751-759](../../src/scenarios/transcode/index.ts#L751-L759) [src/scenarios/transcode/index.ts:855-873](../../src/scenarios/transcode/index.ts#L855-L873) [src/core/oracles.ts:1998-2047](../../src/core/oracles.ts#L1998-L2047) **Consequence:** an adapter may ignore the requested effect and still pass. **Target:** derive effect-aware pixels and assert BT.709/BT.2020/PQ signaling against [ITU-R BT.709](https://www.itu.int/rec/R-REC-BT.709-6-201506-I/en) and [ITU-R BT.2020](https://www.itu.int/rec/r-rec-bt.2020-2-201510-i/en). **Verification:** deliberate no-op adapters fail every transform row they ignore.

6. **Scalar fps and broad duration proxies.** **Current:** metadata compares one numeric fps with ±0.05 and several scenarios use fixed 0.15/0.12-second bands; processed frames are estimated from source nominal fps × duration. [src/core/oracles.ts:162-177](../../src/core/oracles.ts#L162-L177) [src/core/oracles.ts:3920-3938](../../src/core/oracles.ts#L3920-L3938) [src/core/runner.ts:1681-1689](../../src/core/runner.ts#L1681-L1689) **Consequence:** VFR/NTSC representation, edit-list/timebase rounding, priming, and actual output work are partially conflated. **Target:** compare rational cadence/timestamp distributions and modeled presentation duration under [ISO BMFF](https://www.iso.org/standard/83102.html), then count observed output frames. **Verification:** 30000/1001, VFR, edit-list, and primed-audio fixtures each pass inside a documented cause-specific band and fail when one presentation interval is truly lost.

7. **Audio structure and content are under-scored.** **Current:** audio-only transcodes request output shape and duration, but the invariant cannot read Ogg/FLAC/WAV and comments explicitly defer PCM bit-exactness for FLAC and WAV. [src/core/oracles.ts:3738-3762](../../src/core/oracles.ts#L3738-L3762) [src/scenarios/transcode/index.ts:322-423](../../src/scenarios/transcode/index.ts#L322-L423) [src/scenarios/transcode/index.ts:1075-1085](../../src/scenarios/transcode/index.ts#L1075-L1085) **Consequence:** some registered rows resolve `NA_ASSET`, while silence, channel corruption, or severe lossy distortion can pass the covered metadata-only paths. **Target:** add independent Ogg/FLAC/WAV readers and compare decoded PCM after AAC priming/edit-list and Opus pre-skip/end trimming according to [Apple's AAC guidance](https://developer.apple.com/documentation/quicktime-file-format/background_aac_encoding) and [RFC 7845](https://www.rfc-editor.org/rfc/rfc7845.html). **Verification:** every registered audio target yields structural evidence; lossless targets match expected samples after trimming; injected silence/channel swaps fail; legitimate encoder delay does not.

8. **ABR validates files, not switching.** **Current:** the fan-out oracle checks count/order, optional codec/dimensions, playback, and per-rendition SSIM; it does not inspect bitrate, segments, manifest, or aligned access points. [src/core/oracles.ts:1643-1729](../../src/core/oracles.ts#L1643-L1729) **Consequence:** four individually playable files can pass despite being unsuitable for seamless adaptive switching. **Target:** require time-aligned representations and segment/random-access alignment following the [DASH-IF adaptation-set constraints](https://dashif.org/docs/DASH-IF-IOP-v4.2-clean.htm). **Verification:** cross-rendition boundary switching is decoded through every adjacent rung pair with no gap/overlap.

9. **The round trip is not composed.** **Current:** leg two reads a fixed VP9 corpus file, not leg one's result. [src/scenarios/transcode/index.ts:1384-1421](../../src/scenarios/transcode/index.ts#L1384-L1421) [src/core/runner.ts:794-812](../../src/core/runner.ts#L794-L812) **Consequence:** the claimed cumulative-generational-loss property is not measured. **Target:** bind scenario output to the next scenario input and keep the neutral original-source reference for final comparison; WebCodecs' resource model also requires deterministic closure of consumed `VideoFrame` objects during such a pipeline. ([WebCodecs `VideoFrame` resource release](https://www.w3.org/TR/webcodecs/#dom-videoframe-close)) **Verification:** hashes/provenance show leg two consumed leg one's exact bytes, and perturbing leg one changes leg two.

10. **Scale numerator is inferred, and mixed coverage collapses.** **Current:** encoded-byte operations infer frames from source golden metadata; exhaustive aggregation preserves per-file detail and coverage counts but returns whole-cell `FAIL`/`ERROR` if any admissible file fails. [src/core/runner.ts:1668-1723](../../src/core/runner.ts#L1668-L1723) [src/core/runner.ts:1118-1189](../../src/core/runner.ts#L1118-L1189) **Consequence:** cadence-changing throughput can have the wrong numerator, and “file 01 passes, 02/03 fail” loses its first-class partial-coverage grade. **Target:** instrument actual decoded/encoded frame timestamps under the [WebCodecs timestamp/duration contract](https://www.w3.org/TR/webcodecs/#videoframe-interface) and add `partial coverage` while retaining every file status; only valid correctness evidence admits metrics. **Verification:** reports expose measured frame counts, passed/admissible/total, and failing filenames without converting ordinary partial robustness into `ERROR`.
